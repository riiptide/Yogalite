YOGALITE 2021 CODING PROJECT PLAN
Detailed implementation plan for building all Yogalite features in a pre-AI iOS product environment.

Document purpose:
This is a developer-facing implementation roadmap. It describes what to code, in what order, which modules/files to create, which data structures to define, how screens should connect, and what tests should exist before release.

Target platform:
- iOS app
- Swift
- SwiftUI
- Local-first storage
- No backend for version 1.0
- No AI or generative features


1. PROJECT SETUP
================

Goal:
Create a clean native iOS project foundation that can support a complete yoga practice app without needing server infrastructure.

Implementation tasks:

1. Create Xcode project.
   - App name: Yogalite
   - Internal target name may remain Yogapp if already created.
   - Bundle identifier: com.riiptide.Yogapp
   - Deployment target: iOS 18 or chosen minimum iOS version.
   - Interface: SwiftUI.
   - Language: Swift.

2. Create folder structure.
   - Yogapp/
     - Components/
     - Data/
     - DesignSystem/
     - Models/
     - Persistence/
     - Services/
     - ViewModels/
     - Views/
     - Assets.xcassets/
   - YogappTests/
   - YogappUITests/

3. Create design system file.
   - File: Yogapp/DesignSystem/FlowDesign.swift
   - Define core colors.
   - Define spacing constants.
   - Define corner radius constants.
   - Keep color palette calm, warm, and readable.

4. Set app shell.
   - File: Yogapp/YogappApp.swift
   - Add WindowGroup.
   - Load ContentView.
   - Configure SwiftData model container.
   - Prefer light mode for first release if dark mode is not fully polished.

5. Add root view.
   - File: Yogapp/ContentView.swift
   - Decide between onboarding and main tabs.
   - Use @AppStorage("didCompleteOnboarding").
   - Add TabView after onboarding.

Acceptance criteria:
- App launches successfully.
- App can show onboarding or tab UI based on local state.
- Folder structure is clear and stable.
- Tests target can import app module.


2. CORE MODELS
==============

Goal:
Define the domain model for yoga content and practice playback.

Implementation file:
- Yogapp/Models/YogaModels.swift

Data types to create:

1. Pose
   Fields:
   - id: String
   - name: String
   - assetName: String

   Purpose:
   Represents a yoga pose and points to its illustration in the asset catalog.

2. YogaSequence
   Fields:
   - id: String
   - title: String
   - subtitle: String
   - difficulty: String
   - rounds: Int
   - tags: [String]
   - safetyNotes: [String]
   - onboardingNote: String
   - steps: [PracticeStep]

   Computed values:
   - estimatedDuration: TimeInterval
   - estimatedMinutes: Int

   Purpose:
   Represents one complete yoga routine.

3. PracticeStep
   Fields:
   - id: String
   - kind: PracticeStepKind
   - title: String
   - startPose: Pose
   - endPose: Pose?
   - duration: TimeInterval
   - breathCue: BreathCue
   - instruction: String
   - side: PracticeSide
   - endSide: PracticeSide

   Purpose:
   Represents either a timed hold or a transition from one pose to another.

4. PracticeStepKind
   Cases:
   - hold
   - transition

5. BreathCue
   Cases:
   - inhale
   - exhale
   - natural

6. PracticeSide
   Cases:
   - none
   - left
   - right

7. YogaProgram
   Fields:
   - id: String
   - title: String
   - subtitle: String
   - systemImage: String
   - flows: [ProgramFlow]

8. ProgramFlow
   Fields:
   - id: String
   - day: Int
   - sequence: YogaSequence

Acceptance criteria:
- Models compile without depending on UI code.
- Sequence duration can be calculated from steps and rounds.
- Models are Identifiable where needed by SwiftUI ForEach.

Tests:
- Round text formatting.
- Duration/minutes formatting.
- PracticeSide display text.

16. PRACTICE PLAYER VIEW MODEL
==============================

Goal:
Implement the practice state machine independent of UI layout.

Implementation file:
- Yogapp/ViewModels/PracticePlayerViewModel.swift

State:
- sequence
- currentStepIndex
- currentRound
- remainingTime
- elapsedTime
- transitionProgress
- isPlaying
- isPaused
- isComplete
- stepStartedAt
- stepElapsedBeforePause
- timerTask

Computed values:
- currentStep
- nextStep
- canGoToPreviousStep
- overallProgress
- stepProgress

Methods:

1. start(now:)
   - Reset to first step.
   - Set current round to 1.
   - Mark playing.
   - Initialize timer.

2. pause(now:)
   - Tick first.
   - Save elapsed time.
   - Clear stepStartedAt.
   - Mark paused.

3. resume(now:)
   - Mark unpaused.
   - Restart timer loop from now.

4. togglePause(now:)
   - Switch pause/resume.

5. restart(now:)
   - Call start.

6. previous(now:)
   - Guard isPlaying and not complete.
   - Guard canGoToPreviousStep.
   - Move to previous step or previous round.
   - Reset current step.

7. next(now:)
   - Advance step.
   - Complete if last step of last round.
   - Reset current step when not complete.

8. stop()
   - Cancel timer.
   - Mark not playing.

9. tick(now:)
   - Calculate elapsed time.
   - Advance through one or multiple steps if time exceeded.
   - Update remainingTime and transitionProgress.

10. complete()
   - Mark complete.
   - Stop timer.

Acceptance criteria:
- State transitions are deterministic.
- Tests can pass custom dates.
- Timer does not drift badly during pause/resume.
- Previous at first step does nothing.
- Completion happens exactly once.

Tests:
- advancingFromOneStepToTheNext
- pausingAndResumingKeepsElapsedTimeStableWhilePaused
- movingToTheNextRound
- completingAfterAllRounds
- restartingThePractice
- skippingToNextStep
- previousIsUnavailableAtTheFirstStep
- previousBecomesAvailableAfterAdvancing
- overallProgressCalculation

28. FINAL DEVELOPER HANDOFF SUMMARY
===================================

The highest-risk code is the practice player timer engine. Build and test it carefully.

The highest-risk App Review area is visible but nonfunctional UI. Remove it or disable it clearly.

The highest-risk metadata area is privacy. Keep local-only analytics, the privacy manifest, App Store Connect answers, and public policy text aligned.

The highest-value MVP loop is:
Onboarding -> Home -> Sequence Detail -> Practice Player -> Completion -> Profile Stats/Library.

Build that loop first. Polish it. Then expand the catalog and programs.
